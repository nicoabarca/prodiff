Domain Architecture Refactor

Restructuring the SvelteKit frontend of compare into six feature domains, delivered as a five-layer stacked-PR chain on refactor/domain-architecture.

01 What this is

A structural refactor. No functionality, business logic, Tauri command name, route URL, or user-visible behavior changes. Files move, imports are rewritten, one shared file (filters.ts) is split per filter kind, and Vitest is installed.

Two pieces of work that were considered and deliberately excluded are listed under Deferred, at the end. Both are rewrites rather than moves, and putting either inside a ninety-file diff would make a regression hard to bisect.

Scope

~95 files moved or rewritten across src/lib/. Routes keep their URLs.

Verification

pnpm check and pnpm test pass on every layer.

Delivery

Five draft PRs, each stacked on the one below, pushed but not merged.

02 Target domains

Six domains, each owning its components, state, Tauri invokers, invocation contracts, utilities, and tests. Each maps to a Rust module under src-tauri/src/ and, for four of them, to a route under /app/projects/[id]/.

Pinned by tooling, not by preference. components.json declares the aliases $lib/utils, $lib/hooks, $lib/components/ui, and $lib/components. Moving any of them breaks npx shadcn-svelte add, which rewrites those imports on every run. They stay exactly where they are, and components/ui/ keeps its CLI-generated kebab-case filenames.

Conventions

  • kebab-case everywhere, files and folders. Matches the ~150 files in ui/ that cannot be renamed, and avoids case-only renames on a case-insensitive filesystem.
  • Deep imports, no barrels. import type { Slice } from "$lib/slices/types". The dependency is visible in the import line, and there are no re-export cycles to untangle.
  • One invoker file per Tauri command, named after it: invoke("directed_tree", …) lives in tree/invokers/directed-tree.ts and nowhere else. Components call the invoker, never invoke() directly.
  • Tests inside the domain at <domain>/tests/{utils,state,invokers,components}/. Shared components keep their test beside the source instead, since they are not a domain.
  • Rune tests are named *.svelte.test.ts — Vitest only compiles runes in files whose name contains .svelte. This lines up with the source naming for free: slices.svelte.ts → slices.svelte.test.ts.

05 Splitting the filter vocabulary

src/lib/filters.ts (265 lines) becomes one module per filter kind, mirroring what src-tauri/src/filters/ already does. Each kind file owns its type, its modes, its mode-info copy, and its arm of describe and isComplete. filter.ts keeps only the union and the two dispatch switches — the direct analogue of mod.rs::apply_one. Adding a filter kind becomes one new file plus two lines. 

src/lib/filters/filters/       src-tauri/src/filters/
├── attribute.ts               ├── attribute.rs
├── numeric.ts                 ├── numeric.rs
├── timeframe.ts               ├── timeframe.rs
├── endpoint.ts                ├── endpoint.rs
├── duration.ts                ├── duration.rs
├── follower.ts                ├── follower.rs
└── filter.ts   union +        └── mod.rs   Filter enum +
             dispatch                    apply_one dispatch

NumericMode is shared by the numeric and duration kinds, exactly as it is in Rust's enums.rs. It lives in numeric.ts; duration.ts imports it.

06 The stack

Five layers, bottom to top, each a draft PR based on the one below. refactor/domain-architecture is the trunk; it is created off main and stays unmerged until you merge it yourself.

07 Layer by layer

L1 refactor/vitest-setup no files move

Install the test runner before anything moves, so every later layer can be verified with pnpm test as well as pnpm check. The two existing tests are converted where they sit; they relocate in later layers.

  • Add dev dependencies: vitest, jsdom, @testing-library/svelte, @testing-library/user-event, @testing-library/jest-dom.
  • New vitest.config.ts using mergeConfig over vite.config.js, with test.environment: "jsdom" and resolve.conditions: ["browser"]. Kept separate because vite.config.js exports an async factory tuned for TAURI_DEV_HOST, and no test setting should leak into tauri build.
  • New vitest-setup.ts registering the jest-dom matchers.
  • package.json: add test and test:watch scripts.
  • Convert src/lib/virtual.test.ts (64 lines) and src/lib/distributions.test.ts (247 lines) from node:assert + hand-rolled harness to describe/expect. Their Run with npx tsx header comments are deleted.

The filters/slices seam: filters/ knows one filter at a time and nothing about chains, slices, or populations. Chain semantics — effectiveChain's base-then-own ordering — is a slices rule and stays in slices/. filter-editor.svelte takes project and initial: Filter | null as props, emits a Filter, and never touches slice state.

The raw invoke("slice_preview", …) currently inside event-data-table.svelte moves behind slices/invokers/slice-preview.ts. That is the only component in the codebase calling invoke() directly.

08 Judgment calls worth recording

Three decisions that went against the default reading of the target architecture:

Decision Chosen Why
db/schema.ts Stays one file All tables readable in one place is worth more than strict domain ownership. It imports persisted types from four domains, and that is accepted.
statistics/ Separate domain It owns no state and no types — every input comes from slices/. Kept separate anyway so directories map one-to-one to routes, which makes navigation predictable.
project vs event-log Merged into event-log/ Split, they would reference each other in both directions (Project.columns needs ColumnMapping; createProject needs addProject). Rust already treats them as one module.

09 Deferred

Both are recorded in ADR 0004 under Deferred, not as TODOs in code.

Splitting filter-editor.svelte

833 lines, ~18 $state variables shared across kinds, one save() reading a different subset per kind. Splitting it into six per-kind editors is a rewrite wearing a refactor's clothes, and belongs in its own PR reviewed against a working baseline. The per-kind vocabulary split — the part that actually makes adding a filter kind cheaper — is done in L3.

Thinning the four fat routes

distributions 393, new 233, filters 219, tree 176 lines. Extracting their real regions (step picker, toolbar, chart grid, legend) means untangling ~15 $derived values across new prop boundaries, and a $derived chain that silently changes reactivity scope does not fail loudly — it renders stale. Routes keep their URLs and get import fixes only.

End-to-end tests

Not deferred so much as blocked: tauri-driver supports Linux and Windows only, so Playwright cannot drive the real Tauri window on macOS. Testing these flows in a browser would require mocking invoke() and plugin-sql wholesale, at which point the test verifies the mocks. Revisit as its own decision.

10 What verification does and does not cover

Covered by pnpm check: every broken import, every wrong type, every missing export. This is the dominant failure mode of a move-and-rewire refactor, and svelte-check catches all of it.
Not covered: runtime behavior. A wrong invoke argument name is a string, and a $effect whose reactivity scope changed still compiles. Both risky pieces were deferred precisely to keep this residue small, but the click-through is yours — upload a log, map columns, create the project, apply filters, open statistics, build a tree, open distributions.
Stack mechanics: these are move commits, and rebasing renames across each other is where conflicts get unpleasant. git config rerere.enabled true is set before the stack is created. If a fix is needed in an early layer, it is made on that layer's branch and replayed with gh stack rebase --upstack, never committed on top.

11 Execution sequence

# setup
git switch -c refactor/domain-architecture main
git config rerere.enabled true

gh stack init --base refactor/domain-architecture \
  refactor/vitest-setup \
  refactor/event-log-domain \
  refactor/slices-and-filters \
  refactor/tree-and-distributions \
  refactor/shared-and-docs

# per layer, bottom to top
gh stack bottom                  # then `gh stack up` between layers
#   ... move files, rewrite imports ...
pnpm check && pnpm test
git add -A && git commit -m "<caveman-commit subject>"

# once all five layers are committed and green
gh stack submit --auto           # push all branches, open five DRAFT PRs
gh pr edit <n> --title ... --body ...   # real titles and bodies, per PR
gh stack view --json             # confirm the chain

Commit subjects come from /caveman-commit, subject line only. PR titles and bodies are written in normal prose. Nothing is merged: the five PRs stay drafts, and main ← refactor/domain-architecture is yours to open and merge.
